# Курсовая работа «Тестирование API»: функционал «Личные события»

## Задача / О проекте

Продолжение первой курсовой работы: та же функциональность «Личные события» портала преподавателя Skyeng, но на уровне API. Моя роль: анализ документации API-контрактов, проектирование позитивных и негативных API-тест-кейсов, создание коллекции в Postman с тест-скриптами и цепочками запросов, проведение тестирования и оценка готовности бэкенда к релизу.

## Что я делал

- Изучил документацию API (контракты запросов создания/получения/редактирования/удаления личных событий).
- Спроектировал 15 API-тест-кейсов: 10 позитивных (создание событий разной длительности, с описанием-ссылкой, с цветом, в прошлом, получение расписания, редактирование, удаление) и 5 негативных (пустое название, название >40 символов, некорректное время, невалидный токен, несуществующий eventId).
- Создал коллекцию в Postman: разделил запросы по папкам «Позитивный» / «Негативный», настроил переменные (`base_url`, `my_token`, `event_id`, `startAt`), написал тест-скрипты для проверки кода ответа и автосохранения ID созданных событий в переменные для последующих запросов.
- Запустил тест-ран коллекции и проверил все 15 запросов на соответствие документации.
- Оформил 6 найденных дефектов в трекере с шагами воспроизведения, ожидаемым результатом, приоритетом и серьёзностью (Major/Minor/Blocker).
- Дополнил отчёт о тестировании результатами API-тестирования и итоговым решением о готовности.

## Результаты

- Пройдено 15 тест-кейсов: 9 PASS / 6 FAIL — **60% успешных**.
- Позитивные: 8/10 (80%), негативные: 1/5 (20%) — большинство дефектов найдено именно в обработке ошибок и валидации.
- Найдено 6 дефектов: отсутствие валидации обязательного поля `title`, отсутствие ограничения длины названия (40 симв.), возможность создать событие в прошлом, некорректный код ответа при удалении несуществующего события (200 вместо 404), нерабочее редактирование времени события, ошибка авторизации (401) при создании цветного события.
- **Решение: функциональность не готова к релизу** — требуется исправление валидации и повторное тестирование.

## Используемые инструменты

Postman (коллекции, переменные окружения, тест-скрипты на JavaScript), трекер задач (баг-репорты), Yonote (тест-план, отчёт).
