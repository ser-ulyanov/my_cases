## 5. Выводы и рекомендации


### **5.1. Готовность продукта**

На основании проведенного тестирования API функциональности **«Личные события»** можно сделать следующие выводы:

| **Критерий** | **Оценка** |
|----|----|
| Работоспособность основного функционала | Частично |
| Соответствие документации API | Не соответствует |
| Обработка ошибок и валидация | Критические проблемы |
| Стабильность | Требует доработки |

**Продукт НЕ МОЖЕТ быть выпущен в текущем состоянии** без исправления найденных дефектов.

  

### **5.2. Влияние дефектов на пользователей**

1. **Отсутствие валидации обязательных полей** (название события):
   - Пользователь может создать событие без названия
   - В расписании появятся "пустые" события, которые невозможно идентифицировать
2. **Отсутствие ограничения длины названия**:
   - Длинные названия могут ломать верстку интерфейса
   - Возможны проблемы с отображением в мобильной версии
3. **Возможность создания событий в прошлом**:
   - Засорение расписания неактуальными событиями
   - Путаница при планировании
4. **Удаление несуществующего события** (200 OK):
   - Пользователь получает ложное подтверждение об успешном удалении
   - Невозможно отследить реальное состояние системы
5. **Неработающее редактирование времени**:
   - Ключевая функциональность недоступна
   - Пользователь не может перенести событие
6. **Проблемы с авторизацией для цветных событий**:
   - Часть функционала полностью недоступна

  

### **5.3. Рекомендации**

#### **Разработчикам (обязательно к исправлению):**

1. **Добавить валидацию обязательных полей:**
   - Поле title должно быть обязательным
   - При отсутствии title возвращать ошибку с кодом not_valid
2. **Добавить ограничение длины названия:**
   - Максимум 40 символов (согласно требованиям)
   - При превышении возвращать ошибку валидации
3. **Запретить создание событий в прошлом:**
   - Проверять, что startTime >= текущего времени
   - Добавить бизнес-правило "нельзя планировать в прошлом"
4. **Исправить удаление несуществующих событий:**
   - Возвращать HTTP 404 Not Found
   - В теле ответа: "code": "domain_error" с сообщением "Personal event not found"
5. **Исправить редактирование времени:**
   - Проверить логику обновления поля startAt/endAt
   - Добавить тесты на соответствие документации

#### **Команде тестирования:**

1. Добавить автоматизированные тесты в Postman для регулярной проверки валидации
2. Расширить негативные сценарии (спецсимволы, граничные значения)
3. Добавить проверки структуры ответа (JSON Schema)
