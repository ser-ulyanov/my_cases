# Дипломная работа: автоматизация тестирования YouGile (Python + Selenium + pytest)

## Задача / О проекте

Финальный проект, объединяющий все навыки курса: ручное тестирование, тест-анализ и автоматизацию. Объект тестирования — CRUD-операции над проектами (досками) в веб-сервисе YouGile, покрытые автотестами как на уровне UI, так и на уровне API. Моя роль: спроектировать тест-план и тест-кейсы, построить фреймворк автоматизации на Python по архитектуре Page Object Model и реализовать 10 автотестов (5 UI + 5 API).

## Что я делал

- Составил тест-план: объект тестирования, цели, границы (in/out of scope), стратегия, окружение, критерии входа/выхода.
- Спроектировал 10 тест-кейсов в Qase.io: 5 UI-сценариев (авторизация, создание/переименование/архивирование/удаление проекта) и 5 API-сценариев (создание, получение по ID, получение списка, обновление, мягкое удаление проекта).
- Построил архитектуру автоматизации по паттерну **Page Object Model**: страницы (`AuthPage`, `MainPage`) отделены от тестовой логики.
- Реализовал API-клиент (`ProjectApi`) на `requests` с методами создания/чтения/обновления/удаления проекта.
- Настроил конфигурацию проекта: URL окружения в `config.ini`, тестовые данные — в `test_data.json` (через `DataProvider`), без хардкода в тестах.
- Подключил отчётность **Allure** (`@allure.title`, `@allure.story`, `allure.step`) для наглядной трассировки шагов.
- Настроил `pytest.ini` с маркерами `ui`/`api` для раздельного и совместного запуска тестов.
- Учёл межтестовые зависимости в API-сценариях — `board_id`, полученный при создании проекта, переиспользуется в тестах чтения/обновления/удаления одного и того же объекта.

## Архитектура проекта

```
├── api/                   # HTTP-клиент для API проектов YouGile
│   └── project_api.py
├── config/                # провайдеры конфигурации и тестовых данных
│   ├── config_provider.py
│   └── data_provider.py
├── pages/                 # Page Object: авторизация, главная страница
│   ├── auth_page.py
│   └── main_page.py
├── test/                  # автотесты
│   ├── test_ui.py         # 5 UI-тестов (Selenium)
│   └── test_api.py        # 5 API-тестов (requests)
├── conftest.py            # фикстуры pytest (driver, auth_page, main_page, board_api)
├── config.ini             # окружение (UI/API base URL)
├── test_data.json         # тестовые данные (в .gitignore, не публикуются)
├── pytest.ini             # маркеры ui/api, интеграция с Allure
└── requirements.txt       # pytest, selenium, requests, allure-pytest, webdriver-manager
```

## Стек технологий

Python, pytest, Selenium WebDriver, requests, Allure, Page Object Model, configparser.

## Запуск тестов

```bash
pip install -r requirements.txt
pytest -m ui      # только UI-тесты
pytest -m api     # только API-тесты
pytest             # все тесты
allure serve allure-files   # просмотр отчёта
```

## Результаты и статус

Реализовано 10 автотестов из 10 запланированных (5 UI + 5 API). Один UI-сценарий (`test_rename_board`) оформлен как заготовка (шаг переименования не реализован) — зафиксировано как техдолг для доработки. Остальные 9 тестов полностью реализованы и покрывают CRUD-операции над проектами через оба слоя приложения.
