  

## 1. Введение

  

Документ описывает план и кейсы автоматизированного тестирования веб-сервиса **YouGile** (<https://ru.yougile.com>) в части управления проектами (досками). Автоматизация покрывает создание, чтение, обновление и удаление проекта как через **UI**, так и через **API**, согласно требованиям дипломной работы.

  

## 2. Объект тестирования

  

| Параметр | Значение |
|----|----|
| Приложение | YouGile (веб-версия) |
| UI base URL | ```javascript
https://ru.yougile.com/team/
``` |
| API base URL | ```javascript
https://ru.yougile.com/api-v2
``` |
| Тестируемая функциональность | CRUD-операции над проектами (досками) |
| Стек автоматизации | Python, pytest, Selenium, requests, Allure |

  

## 3. Цели тестирования

  

- Проверить корректность работы основного сценария CRUD над проектами через UI.
- Проверить корректность работы API-методов управления проектами.
- Обеспечить регрессионное покрытие критичного функционала перед релизами.
- Настроить раздельный и совместный запуск UI/API тестов через маркеры pytest.

  

## 4. Область тестирования

  

### В область входит

  

- Авторизация пользователя в веб-интерфейсе.
- Создание проекта (UI, API).
- Просмотр проекта / списка проектов (UI, API).
- Переименование проекта (UI, API).
- Архивирование проекта (UI).
- Удаление проекта (UI, API — мягкое удаление).

  

### Вне области

  

- Работа с задачами, досками задач, спринтами внутри проекта.
- Права доступа и роли пользователей.
- Мобильная версия и адаптивная верстка.
- Нагрузочное и производительное тестирование.
- Тестирование безопасности (пентест).

  

## 5. Стратегия тестирования

  

| Уровень | Подход |
|----|----|
| API-тесты | Прямые HTTP-запросы к ```javascript
api-v2
``` через ```javascript
requests
```, проверка кода ответа и тела ответа |
| UI-тесты | End-to-end сценарии через Selenium WebDriver по паттерну Page Object |
| Данные | Вынесены в ```javascript
config.ini
``` (окружение) и ```javascript
test_data.json
``` (тестовые данные/секреты) |
| Отчётность | Allure (```javascript
allure.step
```, ```javascript
@allure.title
```, ```javascript
@allure.story
```) |
| Управление кейсами | Qase.io — кейсы синхронизированы с данным документом |

  

Порядок выполнения API-тестов важен (используется общая переменная 

```javascript
board_id
```

 между тестами создания/получения/обновления/удаления одного и того же проекта). UI-тесты используют API как вспомогательный инструмент для пред-/постусловий там, где это уместно (рекомендация к доработке — см. раздел 10).

  

## 6. Тестовое окружение

  

- ОС: Windows
- Python 3.10+.
- Зависимости из requirements.txt: pytest, selenium, requests, allure-pytest, webdriver-manager.
- Тестовый аккаунт YouGile (не личный, во избежание блокировки — рекомендуется временная почта).

  

## 7. Тестовые данные


Тестовые данные

Хранятся в test_data.json и подгружаются через DataProvider: email, password, token, board_name, updated_board_name, task_name, updated_task_name. URL-адреса и окружение — в config.ini, читаются через ConfigProvider. Захардкоженных данных в тестовом коде быть не должно.

## 8. Критерии входа/выхода

**Вход:**

- Код смержен в основную ветку, окружение настроено, доступен тестовый аккаунт и токен API.

**Выход:**

- Все запланированные тест-кейсы выполнены.
- Все автотесты стабильно проходят (10–12 запусков подряд).
- Отчёт Allure сформирован, дефекты заведены и описаны.
- Линтер (flake8/pylint) не выдаёт ошибок и предупреждений.

  

## 9. Режимы запуска

| Команда | Что запускается |
|----|----|
| ```javascript
pytest -m ui
``` | Только UI-тесты |
| ```javascript
pytest -m api
``` | Только API-тесты |
| ```javascript
pytest
``` | Все тесты |
